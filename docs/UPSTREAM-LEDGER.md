## 0.2.4-cyberaudit.4 动态额度保护（候选）

保持完整官方 v0.2.4 基线，增加自有动态容量待审/连续确认/异常冻结上调；账号卡片的预计美元总费用不作为直接授额依据。首次估算和超过可信容量 20% 的上涨需管理员显式确认；至少三次新鲜查询、30 秒间隔、5% 稳定区间；持久化候选编号防止旧页面、并发或重复确认，普通保存不能授权。显示额度和标准成本准入均冻结上调，数据恢复与容量确认均不清用量或换周期。

修复暂停前复现的三项问题：零用量滚动截止时间在轮询间断后误判重置；移除来源后无法关闭策略；到期/无效参与者误将整个来源置于保护、阻断未开启用户。共享有效成员判定用于轮询、分配、重置、准入和确认。测试另覆盖持续异常改变金额、从大幅异常变成小幅上涨、首次历史估算、跨来源/过期/身份变更/重置候选确认、并发一次成功、在途结算以及普通用户 DTO 隐私。

复用既有池 JSON、事件表、管理员窗口和独立 TG 监控；无依赖或迁移变更。数据长时间过期后重新收集三次恢复证据，不能沿用断连前的恢复次数提前上调。同一已知周期内继续允许可信余量，扣减随后结算和在途预占，持续异常本身不暂停账号；实际耗尽、官方阈值、身份或周期不确定仍拒绝。告警比较上次持久化状态，覆盖时间过期及重启后的冻结/暂停/恢复，不每次轮询重复生成事件。TG 只读新事件元数据并保留原游标，不给通知进程业务写权限。完整固定提交回归和产物校验以发布清单为准。旧 `.3` 忽略新保护状态，发布恢复必须检查完整池状态和分配，不能把无迁移误认为可无条件降级。

## 0.2.4-cyberaudit.3 WS 透传续轮首字修复

修复 `passthrough` 在同一连接后续轮收到不带 response ID 的输出事件时，首字时间漏记的问题。每轮先按显式 response ID 或当前 active turn 定位，再独立记录第一次输出；连接级首字与逐轮计时分开，不用总耗时或零值填充缺失数据。

保持既有首字事件集合及推理／工具输出计入规则，不统一或改变 ctx_pool、SSE 的统计口径；无依赖、配置、安全／额度或迁移改动。`TestPassthroughFirstTokenPerTurnAfterWarmup` 在旧实现第二轮失败，修复后覆盖无输出预热、连续无 ID 文本、工具参数、显式 ID、首字不被覆盖及用量不变，纳入现有受管构建的 Passthrough 竞态回归。

## 0.2.4-cyberaudit.2 WS 空闲保活修复

在完整 v0.2.4 基线上修复共用 coder/websocket 上游适配器：连接建立后由唯一后台读取循环处理消息和 Ping/Pong/Close。ctx_pool 持有租约等待下一轮时、终态后的 rate_limits 等元数据暂未消费时仍响应心跳；ReadMessage/ReadFrame 共用同一有序队列，池与下一轮的既有空闲探测可以正常启用。

队列按 1024 帧及 32 MiB 双重限制（另有单帧读取上限 16 MiB）；慢消费者达到上限时显式关闭并在已排队事件之后报告积压错误，不无限占内存或静默丢消息。终态紧跟关闭时先交付终态，取消读取仍使连接失效，关闭等待后台退出。未更换依赖、模型/推理档位、TTFT 统计口径、请求重放或安全/额度规则，无新迁移。

本地真实 WS 覆盖双向空闲心跳、终态后元数据、同租约两轮工具/用户间隙、文本/二进制顺序、关闭原因、读取取消/超时、后台退出及两种积压上限；受管构建固定重复竞态测试，并保留安全/首帧/续轮/部分输出计费全量回归。修复前已复现无业务读取时上游 Ping 超时；不宣称所有首字延迟均由保活引起，也不保证 max 每轮数秒出字。
