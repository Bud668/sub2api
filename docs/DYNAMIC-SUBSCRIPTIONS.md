### 分组配置与公平性

- 分组设置绑定上游、固定名额、每人分配上限、权重。不再手填下调保护金额；普通订阅生效后不叠加分组日／周／月金额限制。
- 空名额从本周期开始一直保留。分母不随在线人数、消费活跃度或中途加入而缩小，不自动借给正在使用的人。
- 中途加入只能领取本周期空位的现有份额，不重新发放完整上限。名额不足拒绝分配。已使用过的名额即使到期、撤销、删除或转为调试，也保留至该来源确认重置；同用户删除重建不能重复领取。
- 管理员可修改本周期名额数；必须已有可信本周期容量，且没有成员的已用标准成本加在途预占超过修改后的份额。失败时整笔回滚，不留下半份配置或多余名额。缩减仅删除未占用的空位。
- 同源多个分组共同核算，按名额及权重分配标准成本，不把同一个上游当作每个分组各有一份完整容量。卡片在分组名旁显示「固定名额 · N」，说明中区分本组与同源总名额。
- 新建的管理员调试订阅不领取动态份额。普通订阅转为调试后，原已占用名额本周期继续保留；其真实消费仍减少对应上游余量。

### 本周期学习与调额节点

| 上游本周期 7d 用量 | 校验间隔 | 稳定情况下的节点 |
| --- | --- | --- |
| 0～10% | 2 个百分点 | 2、4、6、8、10% |
| 10～30% | 5 个百分点 | 15、20、25、30% |
| 30% 后 | 10 个百分点 | 40、50、60、70、80、90% |

学习、实际分配和卡片下一节点共用同一个分阶段函数，避免前后端各算一套。样本不足三段或异常候选尚未确认时继续按 2 个百分点检查，包括在上游周期中途首次接入的情况。学习证据必须来自本周期、新的不重叠消耗区间且时间间隔至少一分钟；重复读取同一缓存不能累积证据，也不调用模型来制造样本。

达到节点只表示重新计算的条件之一，不代表必然立即改变显示金额。普通自动上调相对上次已生效金额累计至少 $20 才应用，未满门槛不补发；使用实际计算值，不取整成 $20 的倍数。有效容量减少时每次同步、每次请求入场都执行安全收紧，不受节点或 $20 门槛影响。已用额超过新份额的成员保留真实消费，剩余可用为零，停止继续放行。

起步额度为 `min(个人上限, max(20, min(60, 个人上限 × 10%)))`，而非完整上限。这是有限试用预算，不是最低可用量承诺；无足够本周期证据时不无限扩额，可能需要等待。每个确认的新上游周期清除旧学习样本，不以往期容量作为新周期保证。

容量使用上游已有用量数据与本站真实标准成本估计，扣除账号官方 7d 自动暂停阈值之外的部分、实际消费和在途预占；没有额外乘 0.9，也不写死 99%。账号阈值继承、覆盖、禁用仍由官方设置控制。

### 逐请求保护与边界

HTTP 请求及每一轮 WS 都使用同一来源锁、持久预占和幂等结算；预占计入一次，不能用第二个 API Key 或重连重复领取份额。普通成员绑定来源不允许换号绕过；账号 4 的重置不改账号 5 的周期或消费。

**不能承诺未知总容量下的最终绝对均分。** 上游容量尚未测出时，有限起步预算仍有估算风险；单次请求也可能超过历史最大请求成本。预占参考不是任意长请求成本的硬上限，真实账单不得被截断成预占金额。节点加密、空位预留、异常冻结扩额与逐请求收紧降低风险，但不能追回已经实际消耗的额度。回归特别检查容量收缩后超用成员停止、其他空位仍保留，而不是用清账或虚构退款掩盖差额。

### 管理员调试独立周额度

- 已分配订阅入口为「更多 → 设置周额度」。保存后给出明确成功提示，窗口保持打开；读取/保存失败保留输入，不静默覆盖并发修改。
- 新独立表 `admin_debug_quotas` 保存周金额与修订号。首次仅复制原分组周限额一次以保留已有行为；之后不跟随分组金额变化。显式填 0 为不限周金额。修改额度不清用量，低于已用额时不再接新请求。
- 调试订阅不受分组日／周／月金额限制，保留有效期、模型、安全规则和真实费用。卡片只显示本周已用、独立周额度及重置说明，不显示月额度。
- 重置固定跟随分组绑定的上游。临时测试其他 OpenAI 上游（包括 API Key 来源）不会更换重置来源；这些请求仍跟踪预占与结算，不为 API Key 来源增加额度探测。
- 只在来源的真实重置确认后清本周用量。如果管理员正在其他上游执行可计费请求，仅等待该调试订阅旧请求结束后再清周用量，不阻止普通成员重置；等待期间暂停该调试订阅的新请求，保留旧账结算。
- 只清周用量，不清累计用量、月历史或独立周上限。角色以数据库为准，被降为普通用户后不能凭旧调试标记绕过动态规则。

## 配置和分配

入口调整为「分组管理 → 分组动态额度」，编辑分组时也可进入。管理员为分组统一设置来源、每人的分配上限、下调保护和权重。保存后，现有有效普通订阅与后续新增订阅自动继承，不再逐人开启；管理员账号默认也参与分配。

分组配置默认关闭。已有个人 V2 配置在升级时保持原样，只有显式保存分组后才统一应用；未配置分组仅在已有来源和参数完全一致时预填供核对，不自动开启。任何有效成员的旧来源与所选来源冲突，整批保存失败，不部分改额。保存分组后只能从分组调整，旧个人写入接口返回冲突；订阅管理保留实际用量卡片与分组入口。

| 配置 | 规则 |
|---|---|
| 绑定上游 | 当前分组允许的直接授权 OpenAI OAuth 来源；保存后固定，不通过关开换源 |
| 分配上限 | 个人订阅本周期累计额度封顶，不是上游总容量上限 |
| 下调保护 | 必须显式填写，当前实现要求大于 0 且不超过分配上限 |
| 分配权重 | 正数，默认 1；按标准成本份额参与分配 |

### 管理员调试订阅

「订阅管理 → 分配订阅」新增开关，默认关闭，切换用户或重新打开表单恢复关闭。后端仅允许管理员操作且目标账号为管理员；普通用户、自助购买或兑换不能声明调试豁免。管理员身份本身不豁免，必须在分配时显式开启。

开启者不占动态份额、不领取个人动态额度、不绑定单一动态来源，可测试所属分组允许的其他上游。其真实消耗及在途仍计入实际使用的上游余量。有效期、原生分组日／周／月额度、API Key、模型与安全限制保留；此开关不授予管理员权限或跨分组访问。撤销管理员角色后不再获得调试豁免。

开关用于新分配；重复分配已存在的订阅不能切换类型，类型不一致返回冲突。续期保留原标记，不清动态用量或已确认周期。

管理员列表、本人订阅卡片和顶部订阅面板统一显示边框：调试订阅固定紫色并带文字标记；普通订阅按分组 ID 使用稳定颜色，不随排序、分页或刷新改变，预留紫色给调试。只向订阅拥有者及管理员返回展示标记，普通用户不能用此字段修改权限。

下调保护提示统一为「仅用于自动调额，不承诺最低可用量。」不预填示例金额，也不把保护值当作额外余额。

首次开启实际按分配上限起步，保留已有用量。例如上限 $600、此前已用 $180，当前额度为 $600，个人未用为 $420，随后仍受本人在途占用和来源余量约束。生效后独立于分组日／周／月金额限制；原生消费统计仍继续记录。没有足够来源数据时允许保存，显示「等待来源数据生效」；实际激活前以及关闭后继续按原分组规则执行，不清空已有消费。订阅有效期、上游保护、API Key 限额、RPM、并发和模型使用规则继续生效。

自动调额以绑定来源本周期的 **10%、20%、30%……** 为节点。按原始百分比判断，19.96% 不算达到 20%；从 19% 到 32% 只按最新节点重算。同一来源、周期和节点在来源锁内原子发布，不因刷新、重复查询或重启重复发额。63% 中途加入不补跑历史节点，等待 70% 和有效学习样本。

卡片「当前已分配」下用静态刷新图标和月／日、时／分显示真实分配时间，完整时间可悬停查看；缺少记录显示「尚未自动分配」，不用最近同步时间代替。「剩余可用」下显示未来节点，例如上游已到 46% 时显示「下次 50%」。已过但未成功的 40% 节点另列待分配原因，后台仍可重试，不把查看卡片算作成功分配。普通用户只看到通用保护说明，不暴露来源容量和预算冲突细节。

分配按累计消费和权重计算，在个人下调保护与分配上限之间分配，封顶后的余量继续分给未封顶者。删除 V1 的 80%／20% 分配、个人 $5／$10 上调门槛、每 30 分钟上调及首次容量人工批准。

- 初始学习期（无可信容量、无本周期自动分配）保存时，本人的当前额度跟随分配上限；已有上限 $600、实际分配 $500 的配置，保存一次相同值即可应用 $600，保留已用和在途。
- 形成可信容量或已自动分配后，修改上限／下调保护只将本人当前额度约束到新范围，提高封顶值不立即补发差额；等待下一有效 10% 节点。不重分其他人的额度。
- 权重和成员变化在下一有效 10% 节点统一计算。
- 重复保存或关闭再开启保留已用量和已分配标准份额，不重新领取一次分配上限。
- 已用超过新额度时，剩余为 0，不清消费、不退款。
- 只有确认绑定上游真正重置，才为该来源有效开启的订阅开始新周期，并重新按分配上限起步。

下调保护合计超过可信预算时，保留原分配并向管理员提示冲突。来源保护仍决定实际可用量，不能为了满足显示额度而突破上游限制。

## 容量学习与官方保护

来源学习、份额及异常风险按标准费用计算；用户额度、已用和补扣金额按实际计费金额展示。倍率变化不重算历史账单；已发布的用户额度不会随页面刷新或每条账单变化。

只使用同一上游身份、同一 7d 维度、同一确认周期的实际费用增量：

```text
区间总容量估算 = 实际标准费用增量 ÷ (上游已用百分点增量 / 100)
```

学习区间至少 10 个百分点且至少间隔 1 分钟；不再额外乘 0.9 预留 10%。最近最多 3 个样本取中位值（偶数时取较低值）；相对可信容量偏离超过 20% 时，仍需要 3 个独立区间在 5% 范围内一致。反复查询相同百分比不是新样本。分配节点维持每 10 个百分点；它与已取消的额外预留不是同一设置。

旧 V2 已学习容量、历史样本和待确认候选值按原系数换回未预留金额，使用池内 `unreserved_capacity` 标记避免重启或重复读取再次放大。读取只换算视图，正常来源锁事务持久化标记；不改已分配额度、用量、周期、学习时间和异常确认次数。下一次满足条件的分配使用新口径，不靠更新反复补额。

可分配剩余预算 = 学习总容量 × max(0, 官方 7d 阈值 − 当前上游用量) − 此后已结算成本 − 在途占用。阈值按百分比换算；例如总容量 $1,500、阈值 99%，该窗口最多分配 $1,485 对应的资源，最后 $15 不参与分配。实际按累计已用和权重在个人边界内分配；同权重时均分，管理员调试和其他非参与者的真实消费也会减少余量。账号 5h／7d 调度保护独立于节点执行。

学习值仍是估算，不是官方承诺的美元周额度；异步计量、模型配比、价格和站外消费都会影响准确度。用量窗口的预计总费用按整个窗口费用除以用量比例计算，动态学习按有效增量区间计算，去掉 0.9 后两者仍可能不同；不能把页面估算直接作为重置证据或跳过异常样本校验。

异常样本不直接改写可信容量或个人额度。已有可信周期内，查询失败／估算暂缓仍可在已知预算内使用，扣除后来消费和来源风险占用；不能靠异常的 $9,000 估算为耗尽用户补额。缺少可信基线、身份改变、周期待确认或旧周期边界已过时，拒绝无法安全判断的新请求，在途结算继续。

百分比保护统一复用官方账号／全局 7d 自动暂停阈值：账号正值覆盖全局，留空／零继承全局，明确禁用则不使用该窗口阈值。5h 官方调度保护保持原样。来源保护不等待 10% 分配节点；由于在途消费和上游计量延迟，不能保证精确停在 98.000%。

卡片、列表和详情只读本地状态；复用现有额度元数据后台同步，不添加模型探活，也不改变渠道探活频率。重置验证仍需要独立新鲜的元数据证据。

## 保存、在途和结算

保存只做身份／分组／参数／版本校验及事务持久化，不同步等待上游网络或旧账恢复。来源被移出分组或授权失效后，仍允许关闭已有合法绑定。分组先锁来源再锁成员，在同一事务内统一保存；来源不同或版本过期时整批回滚。后台分配前补齐新增成员，首个 HTTP 请求／WS 续轮在来源锁内再次确认继承，避免恰好在分组保存期间新增的订阅绕过限额。重复加载不重复分配，也不补额。

同一来源锁协调保存、准入、分配、结算及重置。每条 HTTP 请求／每轮 WS 固定用户、订阅、来源和周期。开启前的请求也保留归属，后续真实结算更新其归属订阅的持久周期用量。原有周计时和普通手动重置不能清空已生效动态周期。

新请求和 WS 每轮都检查生效规则，不只在建连接时检查。适用范围仍为正常计费模式下的文本 Responses（含 compact、WS）、Chat Completions、Messages；Simple 模式及未接入原子计费的跨平台／图片／音视频入口不在此范围。

计费沿用冻结定价凭证、原有事务和 live／archive 去重。真实用量不按预占估价，迟到结果不换用户或周期。健康长请求续租，不因运行超过五分钟误判为免单。HTTP／WS 断连保留已取得的本轮用量，不把前一轮累计量再扣一次。

## 异常账务

正常结算失败时先做有界恢复。已计费记录只核对状态／缓存，不重复扣款。请求结束或确认失联约五分钟后，仍未结案的受管订阅请求再进行异常分类；配置保存不受分类结果阻塞。

| 当前本地参数 | 行为 |
|---|---|
| 单笔标准费用小于 $5 | 凭证完整、归属匹配、累计未达门槛时可自动由站点承担 |
| 同来源同周期累计达到 $20 | 后续异常进入复核，已承担记录不翻案 |
| 未知金额累计 5 笔 | 触发一次来源周期告警；未知金额始终进入复核，不按零或预占自动免单 |
| 余额账单或订阅归属不匹配 | 不适用小额订阅自动承担，进入复核 |

本次授权发布保留上述金额默认值，没有批量补扣或清除历史账单。自动分类只处理有固定归属和执行状态的受管请求，不猜测旧记录归属。

「订阅管理」刷新按钮左侧显示「待复核」和「站点承担」笔数及已确认金额，未知笔数单列。汇总覆盖当前筛选全部记录，不只当前分页；明细以邮箱识别用户，并分当前周期和历史归档。

人工补扣只使用完整、匹配的原订阅凭证，展示用户实际计费金额；事务重新验证当前状态、原周期和原生计费窗口。未知金额不能按预占补扣，余额账务不从此入口重放。补扣沿用原子计费和去重；处理租约及唯一领取标识阻止重复点击、并发管理员、过期工作进程重复收费。

站点承担显示「已处理 · 站点承担」，不可核实金额另行注明。承担后不再追扣、不退款、不阻塞个人配置；迟到凭证只能补充实际承担金额。异常不再冒充个人活跃在途，但来源保留必要风险预留。已确认费用取代估计风险，已扣过的记录不增加站点损失；原预占保留作参考，不篡改成实际账单。

只在独立确认对应来源重置后，旧周期异常结案归档，不把旧债扣到新周期。#4 重置不操作 #5；未开启者的原生周用量、日／月消费、余额和历史统计不跟随清零。跨周期仍运行的请求只保留必要执行保护。

## 界面与通知

用户卡片突出剩余，「当前已分配」显示本阶段实际已生效额度，不是配置上限。紧凑卡片和完整卡片均常显「首次分配时间／最近实际调额」「下次分配节点：上游用量达到 40%」；没有记录或节点时明确显示等待或本周期无下一节点。时间只使用首次分配或真实金额变化记录，不把未改额的计算、页面刷新或最近同步当作调额。

上游返回的重置时间常显，标注待确认，缺失时显示等待同步，不用本地七天推算。详情显示最近实际变更的前后金额、原因、周期起点及同步／确认时间。管理员列表用紧凑卡片；配置和账务分别展开。已生效动态订阅在用户页、顶部订阅面板、管理员列表和 TG 中只展示动态周期额度，隐藏原生日／月额度；未开启、调试订阅或待生效时继续展示原生窗口。分组启用动态后编辑页隐藏原生金额栏，原值保留供调试、待生效或关闭时使用。

保存成功保留窗口、显示服务器确认值和版本；刷新不覆盖未保存编辑。网络超时或服务端 5xx 后仅回读一次核对版本和字段，不盲目重复写入；不能确认时保留输入并提示待核对。

普通用户只能读取自己的订阅信息，隐藏来源身份、容量样本和管理员诊断；账务查询和处理走管理员鉴权。金额、参数及 JSON 大小／字段继续校验。

独立 TG 监控已同步适配：同一来源周期只发一次累计账务升级提醒；发送预算冲突、保护状态变化和重置结果，不逐笔推送小额自动承担。通知不含提示词、回复、密钥或完整凭证。脚本仍在管理目录单独维护，只读所需列，升级保留已有游标；备机监控保持停用。
